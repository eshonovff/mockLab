{{brand}} колдонгон ар бир катуу чектин жыйынтыгы, ошондуктан ресурс кантип иштеери долбоордун
ортосунда эч кандай тыйынтык болбойт.

## Сурам чектөө

Ар бир долбоор өзүнүн `/m/...` эндпоинттерине карата мүнөтүнө 60 сурам менен чектелген, долбоор
ачкычы боюнча эсептелет — ресурс боюнча эмес, ошондуктан үч ресурсу бар долбоор алардын баары
үчүн бир 60 сурамдык бюджетти бөлүшөт. Ар бир жооп учурдагы терезеде канча сурам калганын
көрсөткөн `X-RateLimit-Remaining` хедерин алып жүрөт, сурам ийгиликтүү болобу же жокпу — так
жүргөн клиент бөгөттөлгөнгө чейин артка чегине алат, кийин гана билгендин ордуна.

Чекти ашырсаңыз, терезе кайра жаңыланганга чейин канча секунд күтүү керектигин айткан
`Retry-After` хедери менен `429 Too Many Requests` жообун аласыз.

```js
async function fetchWithBackoff(url) {
  const response = await fetch(url);
  if (response.status === 429) {
    const retryAfterSeconds = Number(response.headers.get("Retry-After"));
    await new Promise((resolve) => setTimeout(resolve, retryAfterSeconds * 1000));
    return fetchWithBackoff(url);
  }
  return response;
}
```

```jsx
import { useQuery } from "@tanstack/react-query";

function useProducts() {
  return useQuery({
    queryKey: ["products"],
    queryFn: () => fetch("https://{{domain}}/m/demo7k2m9x/products").then((res) => res.json()),
    // TanStack Query already retries failed requests with backoff by default —
    // a 429 here is retried automatically without any extra code.
    retry: 3,
  });
}
```

## Баракча өлчөмү

`limit` демейки боюнча 10 жана 100гө чейин чектелген — көбүрөөккө сурам ката бербейт, ал жөн
эле унчукпай 100гө чейин кыскарат. Ресурстун жалпы `count`уна эч кандай чек жок; чек бир
баракчада канча жазуу кайтарылаарына гана колдонулат. Пагинация опцияларынын толук топтому
үчүн [Сурам параметрлери](/docs/query-parameters) барагын караңыз.

## 10 000 жазуулук иреттөө/чыпкалоо чеги

Иреттөө, чыпкалоо жана издөө 10 000 же андан аз жазуусу бар ресурстарда гана жеткиликтүү. Андан
жогору болсо, сурам дагы деле ийгиликтүү аткарылат жана дагы деле туура баракчаланат, бирок ошол
параметрлер унчукпай эске алынбайт — ката катары эмес, `X-MockLab-Notice:
sort-filter-disabled-above-10000` жооп хедери катары белгиленет, анткени сурамдын өзү жараксыз
эмес. Толук түшүндүрмө [Генерация кантип иштейт](/docs/how-generation-works) барагында.

## CORS

Ар бир `/m/...` жообу `Access-Control-Allow-Origin: *` жана чыныгы `OPTIONS` preflight
иштеткичин камтыйт, ошондуктан эндпоинтиңизди каалаган origin'ден түз браузер JavaScript'инен
proxy'сиз чакырса болот. Бул документтерде сүрөттөлгөн ар кандай маалымат хедерлер (`X-Total-
Count`, `X-RateLimit-Remaining` жана калгандары) `Access-Control-Expose-Headers` аркылуу ачык
көрсөтүлгөн, ошондуктан алардын каалаганы үчүн `response.headers.get(...)` браузер кодунда да,
серверлик же буйрук сабындагы клиентте да иштейт.

## Чын эле чектелбеген нерсе

Катуу чеги жок жалгыз нерсе — `count`, ресурстун жалпы жазуу өлчөмү. Бул — бүт максат: жазуулар
сакталгандын ордуна сурам боюнча генерациялангандыктан, миллион жазуусу бар ресурс серверге он
жазуусу барга окшош эле турат. Жогорудагы чектер кызматты бөлүшкөн ар бир долбоорго карата
адилеттүү кармоо үчүн бар, эч бир өзүнчө ресурс эмне билдире аларын чектөө үчүн эмес.
