## Эндпоинтімді шақыру үшін API кілті немесе аутентификация керек пе?

Жоқ. Эндпоинт URL мекенжарыңыздағы (`/m/{project-key}/{resource-name}`) жоба `key` мәні
сұраныстарды жобаңызға дәл осылай шектейді — жіберетін бөлек API кілті немесе аутентификация
тақырыбы жоқ. Бұл ресурсты жасырын құпиясыз-ақ браузер JavaScript-інен тікелей шақыруға
мүмкіндік береді, бұл маңызды, өйткені CORS дәл осы себеппен әдепкі бойынша қосылған — браузер
коды оны тікелей шақыра алсын деп.

## Неге менің `price_gt=50` сүзгім жұмыс істемейді?

Тек төрт сүзгі жұрнағы бар: `_gte`, `_lte`, `_ne` және `_like` — `_gt` немесе `_lt` жоқ (қатаң
үлкен/кіші, "немесе тең" емес). Дегенмен `price_gt=50` жарамсыз деп қабылданбайды; ол ешбір
танылған жұрнаққа сәйкес келмегендіктен, әдепкі бойынша `price_gt` деп аталатын өріске қарсы
жай теңдік сүзгісі ретінде қарастырылады, ал бұл өріс сіздің схемаңызда сөзсіз жоқ шығар — сон-
дықтан ол үнсіз ешнәрсеге сәйкес келмейді. Бүтін сан өрісінде қатаң теңсіздікті білдіру үшін
`price_gte=51` (немесе `_lte=49`) пайдаланыңыз, немесе генерацияланған ондық санда дәл теңдік
сирек керек болатынын ескеріп, `price` өрісі үшін "немесе тең" шекарасын қабылдаңыз.

## Әр сұраныста бірдей жазбаны кері ала аламын ба?

Иә, әрі сіз мұны қазірдің өзінде істеп жатырсыз — бұл
[Генерация қалай жұмыс істейді](/docs/how-generation-works) беріп тұрған детерминизм кепілдігі.
Түзетілмеген сол бір ресурс кез келген клиенттен, мәңгі, бірдей сұраныс үшін бірдей деректерді
қайтарады — оны жазбасаңыз немесе қалпына келтірмесеңіз. Бұл белгілі бір күтілетін мәндерге
қарсы тест немесе демо скрипт жазуды қауіпсіз етеді.

## Неге менің сұрыптау/сүзгі сұранысым жұмысын тоқтатты?

Ресурсыңыздың `count` мәнін тексеріңіз. Сұрыптау, іздеу және сүзгілеу тек 10 000 немесе одан
аз жазбада қолжетімді; одан жоғарыда олар қате қайтармай, үнсіз сөндіріледі, ал жауапта бұл
болғанда `X-MockLab-Notice: sort-filter-disabled-above-10000` тақырыбы болады. Толық сурет
үшін [Шектер және әділ пайдалану](/docs/limits-and-fair-use) бетін қараңыз.

## Жазбаны жою оның `id` мәнін қайта пайдалануға босата ма?

Жоқ — жойылған жазбаның `id` мәні ешқашан қайтып келмейді. Жою генерацияның өзін болдырмау
ретінде емес, сол id-дың жоқ екенін белгілейтін үстеме өзгеріс ретінде сақталады, сондықтан
дәл сол id ресурс қалпына келтірілгенше "жойылған" дегенді сенімді түрде білдіре береді.

## Екі түрлі UI тілі бір ресурс үшін әртүрлі жалған дерек генерациялай ала ма?

Иә, әрі бұлар әдейі бір-бірінен тәуелсіз. Ресурстың өз жалған дерек `locale` мәні бар — `en`,
`ru` және т.б. — ресурсты баптаған кезде бір рет орнатылады, ол қандай тілде аттар, қалалар
және мекенжайлар генерацияланатынын басқарады. Бұл басқару тақтасының қай тілде көрсетілетінімен
еш байланысты емес; басқару тақтасын бір тілде шолып жүріп, ресурс басқа тілде жалған дерек
генерациялай алады.

## Бүкіл беттің орнына бір ғана жазба қалай аламын?

Тізім жауабынан бұрыннан бар id-ды пайдаланып, тікелей жеке жазба URL мекенжайын,
`/m/{project-key}/{resource-name}/{id}`, `GET` жасаңыз:

```js
const list = await fetch("https://{{domain}}/m/demo7k2m9x/products").then((res) => res.json());
const first = await fetch(`https://{{domain}}/m/demo7k2m9x/products/${list[0].id}`).then((res) =>
  res.json(),
);
```

```jsx
import { useQuery } from "@tanstack/react-query";

function useProduct(id) {
  return useQuery({
    queryKey: ["products", id],
    queryFn: () =>
      fetch(`https://{{domain}}/m/demo7k2m9x/products/${id}`).then((res) => res.json()),
    enabled: Boolean(id),
  });
}
```

## Мұндағы бірдеңе көріп жатқаныма сай келмесе — не істеу керек?

Осы құжаттама бойында аталған әрбір жауап тақырыбы (`X-Total-Count`, `X-RateLimit-Remaining`,
`X-MockLab-Notice`, `Retry-After`) нағыз, тексеруге болатын сигнал, тек ішкі мінез-құлық емес —
сәйкессіздіктің дерлік әрқашан сұраныстың нақты тақырыптары айтып тұрғанынан түсіндіруге
болатыны бар. Бірдеңе бұзылған деп есептемес бұрын, содан бастаңыз.
